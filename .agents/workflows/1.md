1. 檢查使用者是否有附帶參數。
   - `/1` 只負責產生今日資料、日報、structured_data、NotebookLM 乾淨資料源、NotebookLM prompt、知識庫與頻道紀錄。
   - `/1` 不產生 YouTube 標題、封面 Prompt、縮圖素材，也不設定封面視覺主題。
   - 如果使用者明確寫 `主題是...` 或 `專案狀態：...`，才設定：
     `export PROJECT_THEME="使用者提供的市場/專案主題"`
   - 如果使用者只提供視覺風格，例如 `/1 忍者龜`、`/1 黑客帝國`，請提醒使用者視覺主題已改由 `/2` 指定，不要在 `/1` 設定。
   - 如果使用者只輸入 `/1`，則不設定主題，使用日常盤勢預設風格。
   - Podcast 腳本必須優先檢查今日是否有高討論度、高成交量，或 AI 數據觀察焦點中的個股，且同時具備法人/量價矛盾；若有，開場先從該個股切入，再回推大盤。
   - 主要個股段落必須落到「異常數據 → 解讀 → 觀察建議 → 風險提醒」。建議用「追蹤、等待突破、避開、確認」，不得寫成直接買賣指令。
2. 使用 `run_command` 工具，在 `/Users/shenghanchou/Developer/AntiGravity專案/stock-youtube/smart_financial_report` 目錄下執行 `/usr/local/bin/python3 main.py`（若有主題請加上環境變數前綴；不要用 `/usr/bin/python3`，那是缺套件的 3.9）。
// turbo-all
2. 持續使用 `command_status` 監聽腳本直到完全執行完畢。
3. 依退出碼判斷結果（`modules/exit_codes.py`）：
   - `0`：成功，繼續下一步。
   - `2`：資料未就緒（法人榜未發布或日期未對齊），等 2～5 分鐘後重跑。
   - `3`：資料品質閘門擋下，回報閘門內容，不要強制重跑。
   - `4`：Gemini 日報生成失敗；`5`：structured_data 萃取失敗（日報已保留，可用 `scripts/maintenance/resume_daily_persist.py --date YYYY-MM-DD` 補跑）。
   - `6`：缺 API key；`7`：16:10 前不執行。
   - `8`：今日非台股交易日（休市日／週末），未執行；這是正常結束，不要重跑。要補跑最近交易日才設 `ALLOW_STALE_SESSION=1`（指定某個交易日用 `ALLOW_STALE_SESSION=YYYY-MM-DD`，用完移除）。
   - `1`：未預期例外，回報 log 的 traceback。
   - 非 0 時不要進入下一步，也不要宣稱產出完成。
   退出碼為 0 後，主動去找 `reports/` 底下今天最新生成的 `daily_report`、`notebooklm_source` 與 `notebooklm_prompt` 檔案，簡單總結一下重點標題。
   - 給 NotebookLM 投餵資料時，優先使用 `notebooklm_source_YYYYMMDD.md`，不要用戲劇化日報當資料源。
4. 詢問使用者是否要用 `/2 視覺主題` 來產生 YouTube 標題、上架素材與封面 Prompt。
